# 第 8 轮：Worker 事后运行档案

> 状态：**已完成并验证**（2026-08-08）。本轮把逐单元原始审计改为一份可直接
> 阅读的 worker Markdown，同时保留完整模型与工具证据。

## 用户可见结果

每次任务创建 `out/workers/<UTC任务时间戳>/`，每个实际启动的 worker 生成
`<unit>.md`。档案包含任务结局、冻结配置、结束统计和带相对时间的状态时间线；完整
LLM 请求、原始 SSE、工具参数与结果置于折叠区。

## 合并与删除

运行时先流式写 `.tmp-worker-<unit>.jsonl`，worker 结束后逐行渲染临时 Markdown，
再原子发布 `<unit>.md`。发布成功后立即删除 JSONL，因此不再写
`out/audit/<unit>.jsonl`，也不永久保存两份相同证据。渲染失败时保留临时 JSONL 并
向 stderr 报告，防止排查现场随失败一起丢失。

## 逻辑状态

worker 主循环直接记录准备输入、请求模型、等待重试、解释响应、压缩上下文、等待工具、
修正工具参数、修正结构化输出、等待发布、取消和失败。上下文预算、重试延迟、工具缓存/
排队/执行时间、结构校验及压缩前后 token 使用独立事实事件，不由渲染器解析文字猜测。

## 文档调整

README 只保留项目定位、快速启动和文档入口。配置、计划、工具、MCP、结构化输出、缓存、
压缩、输出和验证说明迁入 `docs/usage.md`；运行档案契约单列为
`docs/observability.md`；`docs/design.md` 同步替换当前审计路径和职责。

## 验证

- output 单元测试验证 UTC 目录、完整原始内容、失败结局和成功后删除 JSONL；
- 三协议进程测试验证成功档案包含状态、预算、请求、原始事件、工具执行和结果；
- 结构化修正、上下文压缩、MCP、重试和停滞失败测试均改为验证最终 Markdown；
- release 规模实验使用 1000 worker、并发 200、每单元 3 次 LLM 请求：1000 完成、
  0 失败，恰好生成 1000 份 Markdown，零 JSONL/临时文件残留，峰值 RSS 103 MiB；
- 完整证据需要额外读取和写入一次，当前受控实验吞吐为 72 单元/秒。该数字描述本机
  mock 与当前实验参数，不是供应商环境保证；
- `cargo test --no-fail-fast`：78 个单元测试、18 个进程级端到端测试全部通过；
- `cargo +1.88.0 check --all-targets`、格式检查和差异检查通过。

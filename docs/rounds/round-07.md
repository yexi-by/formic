# 第 7 轮：工具扩展、结构化结果与上下文预算

> 状态：**已完成并验证**（2026-08-08）。本轮把 Formic 从固定搜索工具扩展为
> 可配置的批处理调度中心，同时保持任务总量不受人为上限约束。

## 可观察结果

- 进程只读取当前工作目录的 `config.toml`，LLM 环境变量覆盖文件值；模型上下文
  成为必填配置；Anthropic 的输出上限改由其协议专用配置明确提供。
- worker 只能通过冻结的 `ToolRegistry` 和唯一 `Scheduler` 执行普通工具；内置
  `search`、`read` 与任意用户配置的 stdio / Streamable HTTP MCP 使用同一套
  排队、取消、并发、结果大小和统计规则。
- `--output-schema` 启用经过本地校验的 JSON 结果；未启用时继续发布 Markdown。
- input 范围的只读内置工具支持作业内 singleflight 与 LRU；MCP、output 范围、
  失败和截断结果不缓存。
- 每次 LLM 请求前计算完整上下文预算，必要时压缩最旧的完整工具交互组；摘要只有
  通过固定 schema 校验、确实缩小历史并重新进入预算后才替换内存历史。

## 主要边界

1. 总单元数、总回合数和总工具调用数没有固定上限。`--concurrency`、Scheduler
   有界收件箱及各执行目标 semaphore 只限制同时活动的工作，队列满时等待。
2. MCP 工具由用户通过 allowlist 和 alias 决定，不在代码中固定服务器或工具种类。
   作业启动时完成发现、命名与 schema 冻结；目录变化留到下一作业读取。
3. 结构化提交与压缩提交是 worker 内部协议，不进入普通工具队列，也不能被 MCP
   服务器看到。两类结果都以本地 JSON Schema 校验为权威判断。
4. 路径读取相对启动时打开的根目录 capability 执行，并拒绝绝对路径、`..`、符号链接和
   根目录逃逸；结构数据超限直接报错，文本只在 UTF-8 边界截断并附带明确标记。
5. MCP 传输中断、超时或会话失败不会自动重放原调用；可选重连只服务后续调用，并
   重新核对已冻结 schema。

## 验证证据

- `cargo test --no-fail-fast`：77 个单元测试与 18 个进程级端到端测试全部通过。
  覆盖严格配置、路径安全、缓存合并与淘汰、1000 个调度任务背压、真实假 stdio
  子进程、Streamable HTTP、三协议结构化修正、拒绝与截断、压缩成功与失败语义。
- `cargo +1.88.0 check --all-targets`：以项目声明的最低 Rust 版本检查全部目标通过。
- release 规模实验：5000 单元、并发窗口 1000、每单元 8 次工具回合和 1 次最终
  回合，共处理 45,000 次 LLM 请求；5000 完成、0 失败，峰值 LLM 在途 927、
  工具在途 13，峰值 RSS 642 MiB，墙钟 91.4 秒。
- 本地规模实验显式绕过开发机 HTTP 代理；否则测得的是代理承载能力，不是 Formic
  与 mock 的直接并发能力。

## 未验证范围

没有使用真实供应商凭据，因此不声明固定的供应商缓存命中率，也没有验证特定远端
MCP 服务的实现差异。协议请求稳定性、usage 解析、限流与失败语义由本地受控服务验证。

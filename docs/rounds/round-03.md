# 第 3 轮：并发窗口

> 状态：**已完成并验证**（2026-08-06）。本轮档案同 round-01 模板。

## 目标（可观察结果）

`formic run` 接受 `--concurrency <N>`（必填，N ≥ 1）：每个单元一个 tokio
task，活动槽位有界、排队总量无界；并发不改变语义——单元成败独立、记录按
键原子发布、失败单元汇总按计划文件顺序呈现、退出码不变；单元进度在事实
发生后立即写 stderr。

## 停止线（本轮不做什么）

- 无取消令牌树、无重试预算（第 4 轮）；
- 无历史压缩/token 预算（第 5 轮实测后）；
- 调度器不加 RPM 速率记账、不加跨 worker 去重缓存（见张力记录）；
- 无 web fetch。

## 契约（本轮新增/变更）

- **CLI**：`--concurrency <N>` 必填（design §2 列为调用方必须给出的四样
  东西之一；没有诚实默认值，缺失即启动失败），N = 0 报启动错误（退出码 2）。
- **窗口语义**：取到槽位才创建 task；窗口满时排队的是尚未创建的工作，
  不转化为容量错误。窗口大小的依据是调用方对 LLM 配额的判断。
- **并发下的不变量**：单元成败独立；task panic → 该单元失败
  「内部错误：worker task panic」，不波及其他单元；单元进度即时报告；
  汇总中失败单元严格按计划文件顺序呈现（并发只改变完成时间）。
- **失败语义新增**：`Panicked`（worker task panic，由 catch_unwind 转为
  单元失败）。

## 模块改动

- `src/main.rs`：`--concurrency` 参数与校验；`Arc<JobContext>`；
  Semaphore + JoinSet 驱动（acquire-then-spawn）；task 内即时进度；
  panic 隔离；汇总按计划顺序。本轮唯一实质改动。
- `src/llm/mod.rs`：`Transform` trait 对象补 `Send` 约束（spawn 前提）。
- `src/worker.rs`：新增 `Panicked` 变体；`run_unit` 签名不动。
- 其余模块零改动。

## 决策与设计张力记录

design §5 把「限流记账」「去重缓存」列为调度器不变量，本轮经判断不实现：

- **RPM 速率记账**：窗口 N 就是调用方对配额的表达（§2「唯一的策略选
  择」），没有实测故障证据前不引入第二套限流机制（AGENTS.md §7）；第 5
  轮规模实验与真实供应商联调时用证据决定。
- **去重缓存**：design 的去重针对外部资源（web fetch）；本轮唯一工具
  search 是本地只读幂等，重复执行结果一致，并发下无正确性需求，不为猜测
  中的未来预留（§3）。

调度器第 2 轮形态（串行准入 + 有界 blocking 池 + oneshot）本身并发安全，
本轮零改动，其并发正确性由 e2e 覆盖（三协议主成功均在窗口 2 下运行）。

## 验证证据

- `cargo test`：53 项全绿（45 单元 + 8 端到端），e2e 连跑 3 遍稳定。
  - 新增**窗口证据**：4 单元 + mock 延迟 100ms，`--concurrency 2` 时 mock
    端在途请求峰值恰为 2，`--concurrency 1` 时恰为 1（经真实入口验证窗口
    语义，不是单元推断）；
  - 新增**失败独立**：窗口 2 下单元 2 返回 500，其余照常完成；
  - 新增**汇总确定性**：计划行乱序（unit 2 先 unit 1 后）且均失败，stdout
    「失败单元：2, 1」严格按计划文件顺序；
  - 三协议主成功迁移到窗口 2 下运行（请求断言改为多重集语义）。
- 手工 demo：`--concurrency 2` 复跑通过，产出与审计齐全。

## 后续轮的接缝

取消令牌树（第 4 轮）：运行时级 token → 每 worker child token，挂在
main 的驱动循环与 worker 的 LLM 调用/工具等待上；窗口与 JoinSet 结构不变。

# Formic 文档

这里保存 Formic 当前版本的使用与维护资料。源码和自动化测试决定程序实际行为；文档负责把这些行为解释给操作者和维护者，不保存已经失效的历史版本或开发轮次。

## 使用者入口

| 文档 | 适合什么时候读 |
| --- | --- |
| [详细使用说明](usage.md) | 配置模型、编写计划、运行、续跑、使用图片或 MCP、理解输出与错误 |
| [任务设计](task-design.md) | 判断工作是否适合拆成独立 worker，并编写可验收的 `task.md` |
| [可观测性与排错](observability.md) | 阅读 worker 档案、统计文件、失败状态和规模指标 |

第一次使用时，先看项目根目录的 [README](../README.md)，然后按需进入上述文档。

## 维护者入口

| 文档 | 负责说明什么 |
| --- | --- |
| [项目地图](project-map.md) | 生产入口、模块职责、依赖方向、状态与数据流 |
| [维护指南](maintenance.md) | 修改各类契约时应到哪里改、要保持哪些不变量、怎样验证和发布 |
| [项目级 AGENTS.md](../AGENTS.md) | 只保存长期有效的宏观目标、边界和维护方向 |

维护代码前，至少阅读项目地图和维护指南中与本次改动相关的部分。修改外部行为时，同步更新详细使用说明、配置示例和 README 中受影响的入口信息。

## 文档分工

- `README.md`：项目介绍、适用场景、最短可运行示例和文档导航。
- `docs/usage.md`：面向操作者的完整产品契约。
- `docs/project-map.md`：面向维护者的当前实现地图。
- `docs/maintenance.md`：具体维护方法、检查项、验证命令和发布流程。
- `docs/task-design.md`：如何设计独立单元和提示词。
- `docs/observability.md`：如何理解运行档案、统计和诊断。
- `AGENTS.md`：只保存不会随字段、模块或命令细节频繁变化的项目级原则。

发现多份文档重复解释同一细节时，把权威说明留在上表指定的文件，其他位置只保留简短概括和链接。

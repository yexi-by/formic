# Formic（蚁群）

## 项目定位

Formic 是一个**本地优先、模型无关**的自主任务批处理运行时，以单个 CLI 可执行文件分发，面向个人用户，也可被 Claude Code、Codex 等上层 Agent 当作普通命令行工具直接调用。

它处理的不是传统自动化任务。传统自动化把流程预先写成确定的脚本与规则；而越来越多的任务——通读长篇小说并提取术语、逐条分析上万条记录、逐个判断页面里有没有目标信息——没有固定流程可写，每一步都需要理解与判断。这类任务本质上是**智能体任务**，必须交给一个真正具备智能的执行单元自主完成。Formic 要做的，就是把这种智能批量化。

## 核心抽象

> 海量自主任务 → 一个任务分配一个执行单元 → 给定输入与任务说明 → 多轮「LLM ↔ 工具调用」循环、全程自主判断 → 结构化输出

围绕这条抽象，运行时接管了批量化所需的全部重活：

- 数据切分
- 有界槽位池调度
- API 限流
- 失败重试
- 断点续跑
- 权限隔离
- 结果汇总

## 执行单元（worker，工蚁）

执行单元是完整但一次性的 Agent 会话：

- 领取自己的数据分片与任务说明，独立循环，产出即毁，槽位立即由下一个任务填补。
- 对数据默认只读，结果只能经运行时的统一输出通道持久化到磁盘。
- 它不是任何上层 Agent 的子代理，而是运行时的内部执行单元。

## 输入契约

输入契约保持开放，只约定「数据 + 意图」这一最小内核。一种典型的调用方式：给出一批数据、一份自然语言任务说明、一个并发上限，剩下的交给蚁群。

## 产品形态

Formic 的定位是**基座而非成品**：内核保持通用，场景能力以特化版的形式在其上生长——如同蚁科之下演化出不同蚁种：

- **Atta**：长篇小说术语表抓取特化版
- **Eciton**：海量数据网络抓取特化版
- ……

特化版共享同一套调度内核，只是预置了各自的领域工具链、任务模板与输出格式。
